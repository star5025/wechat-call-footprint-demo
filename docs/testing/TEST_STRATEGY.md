# 测试策略与质量门槛

## 1. 测试金字塔

### Contract Tests

- TypeScript 与 Rust DTO 字段对齐；
- JSON Schema 校验合法/非法 Fixture；
- 未知枚举安全降级；
- 契约 major 不兼容时拒绝；
- `dataRevision` 和 cursor 一致性。

### Domain Unit Tests

- 结果与接通集合分类；
- 时长总和、均值、中位数和最长；
- 跨午夜按日分摊；
- Coverage 合并与缺口；
- Quality 门控；
- 精确去重与排除 overlay。

### Adapter Tests

- 已支持 Schema fingerprint；
- 错密钥与局部页损坏；
- 未知 `room_type` 和消息状态；
- 多分片与重复记录；
- 截断 XML、乱码和异常时长；
- 未知版本 fail closed。

### Integration Tests

- 文件选择到时光墙的纵向链路；
- 扫描取消、重试和崩溃恢复；
- 新索引事务完成前继续读取旧索引；
- correction overlay 在重新解析后保留；
- 清理只删除应用生成数据。

### UI Tests

- 首页、时光墙、小发现和记录导航；
- 年/月/自定义范围；
- Loading、Empty、Partial、Missing 和 Error；
- 键盘导航和焦点恢复；
- 100%、125%、150%、200% 缩放；
- 隐私模式隐藏名称；
- 返回时恢复筛选与滚动位置。

## 2. 统计金标准

维护一套人工审阅 Fixture，逐条标注：

- 是否是通话；
- 类型；
- 方向；
- 结果；
- 接通时长；
- 联系人；
- 去重组；
- 日期归属；
- 预期日/周/月聚合。

首个金标准沿用当前 Demo 基线：

- 通话尝试：22；
- 已接通：16；
- 未接或取消：6；
- 总接通时长：44,352 秒；
- 平均时长：2,772 秒；
- 最长：8,249 秒。

统计引擎必须得到完全一致的整数结果。

## 3. 数据质量测试

必须覆盖：

1. 完整覆盖且零事件；
2. 缺失覆盖；
3. 部分覆盖；
4. 解析失败；
5. 时区未知；
6. 时长缺失；
7. 身份未识别；
8. 待复核重复；
9. 来源冲突；
10. Preview 适配器。

测试不仅断言数值，还要断言相关指标是否被正确隐藏或标记。

## 4. 安全测试

- 路径穿越、symlink/junction 越界；
- 未授权窗口调用敏感 Command；
- XSS 与超大 IPC payload；
- 任意 SQL、ATTACH、扩展加载被拒；
- Secret 不进入日志、错误、panic 和序列化；
- 临时文件在正常、取消、崩溃后清理；
- 原始目录内容哈希不变；
- 更新签名错误和降级被拒。

## 5. 性能基线

首版目标：

| 场景 | 目标 |
|---|---|
| 已有索引冷启动 | 2 秒内可操作 |
| 常用筛选 P95 | 300 ms 内 |
| 时光墙查询 P95 | 500 ms 内 |
| 10 万事件聚合 | 2 秒内（基准机待定义） |
| 扫描 | 流式、可取消、内存受控 |
| 时间轴 | 虚拟列表，滚动无明显卡顿 |

性能目标必须绑定基准机和数据规模，不能直接作为尚未实测的营销承诺。

## 6. 提交质量门槛

合并到 `main` 前：

- [ ] 工作区无意外文件；
- [ ] Contract 校验通过；
- [ ] 单元和集成测试通过；
- [ ] 无密钥、路径或个人信息泄漏；
- [ ] 新 UI 状态有键盘路径；
- [ ] 统计变更更新金标准或附差异说明；
- [ ] 契约变更更新 Schema、类型、示例和迁移说明；
- [ ] 破坏性变更有新 major 版本。
