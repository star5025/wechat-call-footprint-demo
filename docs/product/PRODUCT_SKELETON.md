# 通话足迹：产品骨架与体验基线

> 状态：Phase 1 Baseline
> 基线版本：v0.3 UI Demo
> 目标平台：Windows 10/11
> 更新日期：2026-10-13

## 1. 产品定义

通话足迹是一款完全本地运行的个人微信通话记录回顾工具。它帮助用户查看某位联系人在本机留存数据中的通话次数、时长、日期分布与时间规律。

产品只描述可验证的通信活动，不评价关系，不推断情绪或原因。

### 核心价值

1. **轻松回看**：无需理解专业统计术语，一到两次点击即可看到结果。
2. **结果可追溯**：总时长、时光墙和小发现都能下钻到组成它们的通话记录。
3. **隐私可控**：默认离线、原始数据只读、无账号也可使用、数据可彻底清理。
4. **诚实表达边界**：区分“没有通话”“没有数据覆盖”和“数据无法解析”。

### 明确不做

- 不读取或分析聊天正文；
- 不修改微信数据库；
- 不提供撤回恢复、自动回复或监控能力；
- 不生成亲密度、关系健康度、冷落或情感结论；
- 不默认上传联系人、通话记录、密钥或诊断信息；
- 不因自动读取失败而要求用户关闭系统安全能力。

## 2. 目标用户与核心场景

### 主要用户

- 希望回顾与家人、伴侣或朋友通话时光的个人用户；
- 不具备数据库或开发知识；
- 关注隐私，希望数据留在本机；
- 更偏好轻松、直观的生活类应用，而不是办公报表。

### 关键任务

| 优先级 | 用户任务 | 成功标准 |
|---|---|---|
| P0 | 添加本机微信数据 | 用户理解读取范围并成功完成一次扫描 |
| P0 | 选择联系人 | 1～2 次点击切换，不暴露内部 ID |
| P0 | 查看总通话时长 | 首页打开后无需筛选即可理解 |
| P0 | 查看某天通话 | 从时光墙点击日期进入当天记录 |
| P0 | 查看单次详情 | 从记录列表或日期详情打开抽屉 |
| P1 | 切换年/月/自定义范围 | 范围切换后摘要与时光墙同步更新 |
| P1 | 重新扫描 | 有阶段进度、可取消、不影响原始数据 |
| P2 | 导出统计 | 导出可重新导入的完整数据 |
| P2 | 清理本地数据 | 明确不会删除微信原始文件 |

## 3. 一级信息架构

一级导航在 Phase 1 冻结为以下四项：

1. **首页**：回答“我们聊了多久、最近发生了什么”。
2. **时光墙**：回答“哪些日子留下了通话，分布如何”。
3. **小发现**：展示中性的描述性规律，不做关系判断。
4. **记录**：逐条浏览、搜索、筛选和核验通话事件。

低频能力收进右上角设置抽屉：

- 数据源与重新扫描；
- 本地数据管理；
- 导出；
- 兼容性与关于。

### 页面职责边界

#### 首页

必须包含：

- 当前联系人；
- 总接通时长；
- 接通次数、语音/视频摘要；
- 最长一次、常见时刻等 2～3 个故事卡；
- 最近通话趋势；
- 最近一次通话；
- 进入时光墙和记录的快捷入口。

不得演变为多筛选器、多表格的 Dashboard。

#### 时光墙

必须包含：

- 一年、一个月、自定义范围；
- 每日热力格；
- 活跃日、总次数、总时长、最活跃日期；
- 颜色图例；
- 无覆盖、无记录、未来日期的不同表达；
- 点击日期查看当天记录。

#### 小发现

只展示满足质量门槛的固定模板洞察，例如：

- 常见开始时段；
- 通话时长分布；
- 活跃星期；
- 连续出现记录的日期。

每条发现都必须可解释、可下钻，并附“只描述记录”的边界说明。

#### 记录

必须包含：

- 日期分组；
- 类型、结果和搜索筛选；
- 时间、方向、类型、结果和时长；
- 单条详情抽屉；
- Unknown 与低置信度状态；
- 数据来源和质量信息的渐进披露。

## 4. 核心用户旅程

### 4.1 首次使用

```text
欢迎与隐私承诺
→ 选择数据获取方式
→ 系统权限预说明
→ 确认账号和数据源
→ 扫描预检
→ 阶段化扫描
→ 结果复核
→ 首页
```

首个正式版本至少提供：

- 导入已解密数据库或规范化文件；
- 取消扫描；
- 部分成功说明；
- 扫描结果中的覆盖范围、事件数和待复核项。

### 4.2 日常回顾

```text
打开应用
→ 自动恢复上次联系人和范围
→ 首页查看摘要
→ 点击故事卡/趋势/最近一次
→ 查看记录详情
```

### 4.3 从时光墙下钻

```text
进入时光墙
→ 选择年/月/自定义范围
→ 悬停/聚焦查看日期摘要
→ 点击日期
→ 当天记录抽屉
→ 点击单次通话
```

### 4.4 数据异常

```text
发现统计不完整
→ 轻量提示说明受影响范围
→ 查看数据质量详情
→ 重试/重新授权/导入副本/保留警告
```

## 5. 视觉与交互基线

v0.3 被确认为后续设计基线。

### 必须保持

- 消费级个人应用气质；
- 柔和紫、蜜桃、薄荷等渐变；
- 大圆角、轻阴影和留白；
- Bento 故事卡与大数字；
- 导航精简，低频功能渐进披露；
- 一到两次点击完成高频任务；
- 文案自然、温和、少术语；
- 图表有等价文字摘要和键盘入口。

### 必须避免

- 左侧后台管理式导航；
- 首页堆叠表格、筛选器和技术状态；
- 大量边框、灰色字段和英文 KPI；
- 用颜色作为唯一信息；
- 让用户看到 JSON、数据库表名、哈希、内部 ID 或密钥；
- 在主流程中展示解析器、Schema 等工程术语。

## 6. 状态设计矩阵

每个核心页面至少实现以下状态：

| 状态 | 用户看到什么 | 可执行操作 |
|---|---|---|
| Loading | 保留布局的骨架，不闪烁整页 Spinner | 取消长任务 |
| Ready | 正常内容与最近更新时间 | 浏览、筛选、下钻 |
| Empty | 说明为何为空 | 添加数据、清除筛选 |
| No coverage | 明确“没有可读取数据”，不显示为 0 | 查看数据源 |
| Partial | 显示可用结果与受影响范围 | 查看质量、重新扫描 |
| Unsupported | 解释版本尚未支持 | 导入副本、导出诊断 |
| Error | 发生了什么、原数据是否安全 | 重试、降级、查看详情 |
| Offline | 核心功能继续可用 | 可选稍后检查更新 |

### 三种空白必须区分

1. `complete + 0 events`：覆盖完整，当天没有通话；
2. `missing coverage`：没有可读取数据，不能判断；
3. `parse failed`：存在数据，但无法可靠解析。

## 7. Phase 1 冻结与延后项

### 当前冻结

- 产品定位与隐私边界；
- 四项一级导航；
- v0.3 视觉方向；
- 首页、时光墙、记录的职责；
- 联系人切换入口；
- 单条详情采用右侧抽屉；
- 年/月/自定义时光墙；
- 统一领域模型与 API 契约采用版本化 DTO；
- Demo 数据模式必须长期保留。

### 暂不冻结

- 所有图标最终素材；
- 深色主题；
- 小发现的完整数量与排序；
- PDF 报告视觉；
- 高级统计、异常和变化点；
- macOS 导航细节；
- 自动读取的最终权限流程；
- 应用商店发行方式。
